# STELLA — 偶像大师全系列角色档案与灵魂设定集

> **S**TELLA **T**reasury of **E**very **L**ive-stage **L**ore & **A**rchetype
> *把每一盏舞台灯亮起时的传说与原型，收进同一座星图。*

**STELLA** 是一个面向 **AI 角色扮演、桌宠交互（Desktop Pet）与 Agent 人格构建** 的结构化角色设定知识库，收录 **《偶像大师》系列七大企划共 336 位角色** 的深度分析档案与灵魂核心设定（合计 **672 份 Markdown 文档**）。

每位角色均采用**「事实记忆 + 灵魂核心」双文件结构**：`A_<角色名>.md` 系统沉淀客观经历、人际网络与 `IF-THEN` 行为规则；`soul.md` 将其高密度提炼为可直接注入系统提示词（System Prompt）的性格内核与对话写作指南。

## ✨ 命名巧思（Why "STELLA"?）

- **英文递归缩写（Recursive Acronym）**：**S**TELLA **T**reasury of **E**very **L**ive-stage **L**ore & **A**rchetype —— 首字母 `S` 递归回库名 **STELLA** 本身，落在 `-ella` 这个拉丁指小词尾上，读起来像一句完整的英文名词短语：*「STELLA：每一段现场传说与原型之宝库」*。Library、Archive 之类的词都太大太硬，Treasury 恰好是「珍藏之所」的意思——它不必装下全部，只需装下值得反复打开的那部分。

- **STELLA 是拉丁语的「星」**。这个星不是天文学意义上的坐标，而是**共通的意象**：765PRO 的星井美希，346PRO 灰姑娘们仰望的那一颗，315PRO 每个人从别的职业折返时抬头看见的那一颗，283PRO 的 *shine*，还有 **初星学園**——校名直译就是「第一颗星」的学校。五家事务所，一句没写下来的共识：**灯光暗下去之前，先有一颗星亮起来**。

- **数字里的谐音也是星图的一部分**。765 = ナムコ（Namco），346 = ミシロ（美城），315 = サイコー（最高），283 = ツバサ（翼）——四组数字不是编号，是四句被念出来的口号。它们指向的不是同一个组织，却指向同一种语法：**把数字念成名字，把名字念成愿望**。

- **词源上的三层回响**：
  - **STAR** 与 **STELLA** 同源，都可上溯到原始印欧语 \*h₂stḗr（星）。英文的 star、德文的 Stern、拉丁的 stella，是同一颗星在不同语言里留下的三个影子。
  - **STELLAR**（恒星的、卓越的）由 stella 加形容词词尾 -āris 构成。偶像工业最爱用的那个词——"stellar performance"——字面上说的正是「像星一样」。
  - **STAGE** 与 STELLA **不同源**（stage 出自拉丁 *stare*「站立」，经古法语 *estage* 而来），但两个词的起首 `STA-` 在字形上并肩而立。这个并非巧合的巧合，恰好是本库想写下的那句双关：**人先站上舞台（stage），然后才成为星（stella）**。词源学不承认它们同宗，舞台史承认它们同命。

- **末尾的 `-A`**：S、T、E、L、L、A 六个字母，六个环节——企划、文本、人群、现场、传说、原型。闭环落在 Archetype 上，因为这套库最终要交付的不是资料，是**可以被人格引擎直接驱动的原型**。

## 🧩 双文件设计规范

每个角色目录严格包含两份互补文档。分工不是「长版/短版」，而是**两种不同的读取方式**：一份供检索，一份供扮演。

### 1. `A_<角色名>.md` — 角色深度分析档案

- **定位**：全量事实记忆库与精细行为规范手册。它是这个角色的**证据链**——每条判断都能回溯到作品、话数、卡面或台词。
- **适用场景**：RAG 检索增强、长上下文设定查阅、精细化剧情推演、人际称呼与时间线校验。
- **固定结构**：

  - **基础样貌与身高** —— 身高、发色瞳色、发型与标志性饰品、视觉印象（一句「看到她你会想到什么」）、**未公开/区分项说明**、生日/星座、血型、个人代表色（含 HEX 参考）。
  - **PART A：角色记忆 —— 客观事实与经历**
    - `基本身份`：姓名（中文／日文／罗马音）、出身、学校年级或事务所、所属组合与派生组合、担当定位、家庭成员、生日星座、身高血型、兴趣、特技、喜恶、CV、代表色——全部结构化表格。
    - `人生关键事件时间线`：按 **前史 → 第一阶段 → 第二阶段 → 第三阶段** 分层推进，每条尽量带作品名与话数／卡面名等可核查线索。前史单列，因为「她为什么会变成现在这样」比「她经历了什么」更重要。
    - `重要关系`：对象／关系性质／**双向称呼方式**（她→对方、对方→她）／核心互动动态。至少 5 行，S 级至少 7 行。
    - `核心信念与价值观`：3–5 条，每条以日文原句口号起头，再中文阐释。
    - `习惯与日常`：可演出的生活细节，4–7 条。
  - **PART B：角色人格 —— 行为模式与表达风格**
    - `Layer 1：身份锚点`：自我认知（早期／中期／后期）＋ 他人眼中的她（至少 3 位角色各自的一句话评价）。
    - `Layer 2：表达风格（CRITICAL）`：语气基调 200–400 字（第一人称、句尾、节奏、音量、用词层级，并分 **默认常态／情绪高涨／动摇低落／认真剖白** 四语境）＋ 典型口头禅与句型表（日文原话＋中文对照）＋ **称呼方式对照表**（S 级 ≥6 行，A 级 ≥5 行，B 级 ≥4 行）＋ 语境声调变化表。
    - `Layer 3：情感与决策模式`：情绪表达（喜悦／沮丧／愤怒／感动四通道）、决策风格（编号 3 条）、冲突应对（外部质疑 vs 亲近之人）、压力应对机制（3–5 条具体行为）。
    - `Layer 4：行为规则`：身体习惯与小动作 4–7 条（可直接演出）＋ **`IF … THEN …` 行为规则集**（S 级 ≥6 条，A 级 ≥5 条，B 级 ≥4 条）。
    - `核心矛盾与成长轨迹`：3 条核心矛盾 + 3 段成长弧线。
    - `代表台词精选`：台词／出处与情境／角色意义三列（S 级 ≥4 行，A 级 ≥3 行，B 级 ≥2 行）。
    - `关键物品与意象`：物件及其象征意义。
  - **结尾**：`总结关键词`，8–12 个顿号分隔词，供向量检索与标签抽取。

### 2. `soul.md` — 角色灵魂核心

- **定位**：高密度人格灵魂摘要。它是这个角色的**可执行文件**——丢进 System Prompt 就能开口说话，且不会在长对话里漂移。
- **适用场景**：直接作为 AI Agent / 桌宠（Desktop Pet）的核心人格提示词（`SOUL.md`），在极小的上下文开销下稳住灵魂、语癖与情绪张力。
- **固定结构（全库统一）**：

  1. **核心驱动力** —— 三条，每条一句她的原话作标题，配 150–300 字阐释。第一驱动力是她自己会说出口的，第三驱动力往往是她不会说出口的。
  2. **价值观与信念** —— 三条，各 120–250 字。
  3. **情感核心** —— 情感底色／情感软肋／情感表达方式，各 120–250 字。
  4. **内在矛盾** —— 三组 `A vs. B`，写明她每一次选择的真实成本。
  5. **成长弧线** —— 三阶段，每段 80–180 字，只写清「从什么变成什么」。
  6. **她在团队里的位置** —— 一句定位比喻 ＋ 150–300 字说明她的不可替代性；内含 **`桌宠写作要点`** 子块：
     - **默认语癖**：第一人称、句尾、语速、常用感叹词。
     - **核心开关**：① 触发 A → 反应；② 触发 B → 反应；③ 触发 C → 反应。
     - **固定称呼**：她怎么称呼队友、制作人、粉丝。
     - **核心互动氛围**：60–120 字，一个「和她在同一空间」的具象场景。
  7. **一句话灵魂总结** —— 40–90 字，可独立成立、脱离上下文仍能辨认出是谁。

## 📏 深度分级

全库按**角色数量 × 文本密度**分三档。分级的逻辑不是「谁更重要」——每位偶像在自己的企划里都是主角——而是**档案需要承载的设定体量**与**该系列可核查素材的厚度**：

| 级别 | 适用系列 | `A_<名>.md` | `soul.md` |
|---|---|---|---|
| **S（深档）** | 本家 765PRO、闪耀色彩、学园偶像大师、vα-liv | **≥ 5,000 字**（5,500–7,000） | **≥ 1,800 字**（1,800–2,400） |
| **A（标准档）** | 百万现场、SideM | **≥ 3,000 字**（3,000–4,000） | **≥ 1,000 字**（1,000–1,400） |
| **B（精简档）** | 灰姑娘女孩 | **≥ 1,500 字**（1,500–2,000） | **≥ 600 字**（600–900） |

**分级理由**：

- **S 级四家，人数都少，但每家都「一个人一层楼」。** 本家 13 人自 2005 年累积近二十年，每人横跨街机、Xbox、SP、OFA、白金星光、星光舞台、TV 动画、剧场版与无数广播剧，素材密度是全系列最高的；闪耀色彩 28 人以 *シャニソン* 的单元剧与 *シャニアニ* 的双线叙事把「偶像的自我怀疑」写成了文学，28 人撑起四部 TV 动画的剧本厚度；学园偶像大师 14 人每人有独立的 *SENSE*／*H.I.F.* 成长曲线与初星学園课程体系，且多数角色的官方资料仍在披露中，需要大量「未公开」标注与边界说明；vα-liv 仅 3 人，却是 3.0 VISION 的起点，且身份结构最特殊——**直播者（ライバー）与偶像候选生的双重身份**，写薄了会直接失真。
- **A 级两家，人数中等，素材集中。** 百万现场 39 人共享 765THEATER 这一舞台与 *ミリシタ*／*ミリアニ* 两条主线，每人有专属曲与剧场公演片段，够写 3,000 字而不注水，但不足以支撑本家级的媒体谱系。SideM 49 人分 16 个组合，组合叙事（ユニットドラマ）强于个人叙事，每人 3,000 字恰好覆盖「前职 → 转行 → 组合内位置」这条主干。
- **B 级一家，人数压倒性地多。** 灰姑娘女孩 190 人，其中大量是无语音偶像，官方素材以卡片台词与剧场版短篇为主，硬写 5,000 字只能靠想象填充——那正好违背本库「未公开就写未公开」的红线。1,500–2,000 字是「材料的真实密度」与「扮演所需的完整度」的交点：足够写清说话方式、关系网与三条行为规则，不至于注水。

字数按中文字符计（不含空白与 Markdown 符号）。**宁可信息密度高，也不要注水重复。**

## 🚀 使用建议

**一、桌宠 / 轻量对话 Agent** —— 只加载目标角色的 `soul.md`，作为 System Prompt 的主体。这个级别不需要事实档案：`soul.md` 的「**桌宠写作要点**」已内置默认语癖、三个情绪触发开关、固定称呼与场景氛围，接上即用。建议在 system prompt 末尾追加一行约束：*「不要复述设定，除非被问起设定」*——桌宠破功通常不是因为不知道，而是因为太想证明自己知道。

**二、深度扮演 / 多角色剧场** —— 以 `soul.md` 锚定性格底色，把 `A_<角色名>.md` 接成知识库或按需抽取段落。多角色同场时，**只抽取每人的三块**：`PART A 重要关系`（防止称呼错辈分）、`PART B Layer 2 表达风格`（防止语气趋同）、`Layer 4 IF-THEN 行为规则`（让反应有分歧）。三块加起来通常是原档的 30%，却是差分度的全部来源。同系列角色同场时，务必让每人的**称呼表**都进上下文——跨企划混演（如 765 前辈与剧场组同台）时最常翻车的不是性格，是叫她「春香さん」还是「春香ちゃん」。

**三、RAG 检索** —— 把 `A_<角色名>.md` 按固定标题切块（骨架全网统一，为的就是这个），`soul.md` 单独作为一个高权重块常驻。检索时加元数据过滤：`series`、`unit`、`depth_level`、`timeline_stage`。**时间线防串线的关键**是给每个 chunk 打上时间阶段标签——本库档案的时间线是分层的（前史／第一阶段／第二阶段／第三阶段），检索命中后先看它落在哪一层，再决定这一层的事实是否适用于当前对话的时点。若需限定某个时期（本家街机期 vs 剧场版期、CG 的 *デレステ* 线 vs *U149* 线、ML 的 *ミリシタ* vs *ミリアニ*、学マス 的入学前后、初星学園 各学年进度），直接读该角色档案的「**未公开/区分项说明**」与时间线小标题，那里写着哪些设定属于哪个时期。
